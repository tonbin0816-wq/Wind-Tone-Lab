# リードに楽器種別を入れる(F-87 / 便AY)── 凍結仕様

2026-09-25 本人:「リードに楽器種別の概念をいれます。たとえばバンドレンのトラディショナルには
アルトもソプラノもテナーもバリトンも全部あるからです」。モック:
https://claude.ai/artifact/HUzQupRwZuDsXY9n7ytcdn(版2 = 本人 OK)。

語彙は `SAX_PRESETS`(App.jsx)のキー `soprano / alto / tenor / baritone` と、表示の `S.Sax / A.Sax / T.Sax / B.Sax`。
**新しい語を作らない**(「楽器種別」「楽器」)。

## 決定(本人)

- **D1 既存のリード**: 楽器種別が無いリードは、そのリードに紐付いた計測(`sessions` の `reedId`)の `saxType` から推定する。
  いちばん多い楽器。同数なら、その中でいちばん新しい計測の楽器。紐付いた計測が1件も無ければ `alto`。あとから編集で直せる。
  - 【2026-09-25 統括の裁定】推定は**箱ごと**にする。楽器を持たないリードは、**古い鍵(メーカー|番手|開封日)で
    同じ箱だった仲間**をまとめ、その箱の全員に紐付いた計測を合算して、上の多数決(同数は最新の計測の楽器、
    計測が1件も無ければ `alto`)で決めた楽器を**箱の全員**に入れる。理由: 箱は実物の1箱なので、同じ箱のリードは
    同じ楽器。1枚ずつ推定すると箱が割れ、番号も振り直されてしまう。既に楽器を持つリードは触らない
    (同じ古い鍵に「楽器あり」と「楽器なし」が混ざる場合、楽器なしの側だけで箱として推定する)。
  - 【2026-09-25 統括の裁定】計測の読み込みが**失敗した**ときは推定を走らせない(書かない)。成功したときだけ走らせる。
- **D2 計測タブ**: リードを選ぶ一覧(箱・開封日・個体)に、**いま選んでいる楽器のリードだけ**を出す。
  楽器を切り替えたとき、選んでいたリードが別の楽器のものなら **選択を外す**(`selectedReedId = null`)。
- **D3 「計測へ」**: リードの詳細から計測タブへ進むとき、計測タブの楽器(`saxType`)もそのリードの楽器にする。
- **D4 比較**: 同じ楽器のリードどうしだけを比べる。
- **D5 一覧の見せ方(A案・全部押せる)**: リードタブ「登録」の一覧の上(`登録 | 比較` の下)に
  S.Sax / A.Sax / T.Sax / B.Sax の**チップの行**。人物紹介・マイページの楽器の行(src/community/screens.jsx の `Chip`)と
  **同じ見た目**(当たり 44 / 見えるピル 30・角 pill・枠 1px・選択中は枠と字が `--c-accent`、それ以外は枠 `--c-line-strong`・字 `--c-ink-2`・字 `--fs-xs` 600)。
  - **4つとも押せる。リードが無い楽器も薄くしない**(本人指示)。
  - 最初は計測タブで選んでいる楽器(リードタブを開くたびにそこから始まる。保存しない)。
  - 見ている楽器の箱だけを並べる。箱の見出しに楽器名は足さない。
  - その楽器のリードが無ければ、一覧の場所に `B.Sax のリードはまだ登録されていません` の1行だけ(既存の空の文言と同じ体裁)。
    「長押しで編集」の案内は、その楽器の箱が1つ以上あるときだけ。
  - 右下の ＋ で開く登録のシートの一番上に「楽器」の行(既存の `OptionPills`)。初期値は**一覧で選んでいる楽器**。
  - **比較**のタブも同じチップの行を持ち、選んだ楽器のリードだけを候補に出す。重ねるグラフの横軸はその楽器。

## 統括の決定(影響範囲の対処)

- **E1 データ**: リードに `saxType` を持たせる。登録のシートで選んだ楽器を書く。箱の編集のシートにも「楽器」の行を足し、
  箱の全員の `saxType` を書き換えられる(同じ鍵の箱があれば既存どおり合流)。
- **E2 箱の鍵**: `reedGroupKey` に楽器を含める(同じ日に開けた Traditional 3.0 でもアルトとテナーは別の箱)。
  `reedBrandGroupKey` も同じ判断で楽器を含める。合流(`applyBoxEdit` / `updateGroup`)も楽器を含めた鍵で判定する。
- **E3 読むときの既定**: `saxType` が無い(または知らない値の)リードは、推定が走るまでの間 `alto` とみなす
  (D1 の「計測が無ければ alto」と同じ値)。読む場所は1つの関数に集める(例 `reedSaxTypeOf(reed)`)。
- **E4 推定の走らせ方**: 純関数(例 `backfillReedSaxTypes(reeds, sessions)`: 変更が無ければ**同じ配列を返す**)にし、
  **計測(sessions)の読み込みが終わってから**走らせる(読み込み前に走ると全部 alto になる)。
  起動のたびに走る形にする ── 古いバックアップを戻すと楽器種別の無いリードが戻るため。変更があったときだけ `setReeds`。
- **E5 リードの詳細**: 見出しのメタ(`reedDetailMetaParts`。正典 #15a の空き枠)に楽器名(`SAX_PRESETS[..].label`)を入れる。
  詳細のグラフ(`MetricTabCard` 等)の横軸は、グローバルの `saxType` ではなく**そのリードの楽器**で引く(今はバグ)。
- **E6 過去の計測にリードを付け直すシート**(データタブ `SessionEditSheet` → `ReedPickSheet`): **その計測の楽器**
  (`session.saxType`。無ければグローバルの `saxType`)のリードだけを出す。すでに付いている別の楽器のリードは外さない(表示は今のまま)。
- **E7 すべてのセッションのリードの絞り込み**(`AllSessionsPage` の選択肢): 各リードの表示に楽器名を添える(例 `A.Sax · …`)。
  - 【2026-09-25 統括の裁定】選択肢だけでなく、**絞り込みピルの表示**(`reedShortLabel`)にも同じく楽器名を添える
    (例 `A.Sax · V16-3 #1`)。箱の鍵に楽器が入ったので、リード名は楽器違いで同じ綴りになり得るため。
- **E8 触らない**: コミュニティ(カタログの別の仕組み)、目安(リードを参照しない)、ピボット(楽器の次元が既にある)、バックアップの形式。
  - 【2026-09-25 統括の裁定】ピボットの**「リード(個体)」の次元だけは直す**。リード名(`reedLabel`)は楽器違いで
    同じになり得るので、束ねる鍵をリードの id にし、表示は `A.Sax · ` を前に付ける(E7 の選択肢と同じ形)。
    他の次元(楽器種別・メーカー・番手 など)は触らない。

## 合格ライン

1. 既存の検査(vitest / pitch-test / build)が全部通る。pitch-test が**古い決まりを固定している検査**(箱の鍵の形・
   `ReedBoxSheet` の `OptionPills` の数・`reedDetailMetaParts` の文字 など)は、新しい決まりに書き換え、各所に `【便AY】` の注記。
2. **振る舞いの検査を足す**(綴りではなく実際に走らせる):
   - 推定の純関数: 多数決 / 同数は最新 / 紐付けなしは alto / 既に値のあるリードは触らない / 変更なしは同じ参照 / 知らない値は推定し直す。
   - 箱の鍵: 楽器だけが違う2枚が別の箱になる。
   - 計測タブの候補の絞り込みと、楽器を替えたときに選択が外れる判定(純関数に出して検査するか、描いて確かめる)。
   - リードタブ: チップ4つが全部押せる / 押した楽器の箱だけが出る / 空の文言 / 登録シートの楽器の初期値が一覧の選択。
   - 付け直すシートの候補がその計測の楽器だけ。
3. 正典(design/canvas)にリード一覧の描写があれば追随する(無ければ不要)。
