## 1. 面（カード）の作法

```
ページの地   --c-sunk (#F6F7F9)      ← 従来は白
カード       --c-surface / radius 16 / padding 16 / --shadow-card
小さいカード --c-surface / radius 12 / padding 10px 14px / --shadow-row
カードの間   12px の余白             ← 罫は1本も引かない
```

- **罫（`--c-rule` / `--c-line` の横線）を新しい画面に1本も引かない。**
  群はカードと余白だけで切る（本人「むやみに線をひくのやめて」）
- 影は2段:
  - `--shadow-card: 0 1px 2px rgba(18, 31, 50, .04), 0 6px 16px rgba(18, 31, 50, .06)`
  - `--shadow-row:  0 1px 2px rgba(18, 31, 50, .04), 0 6px 16px rgba(18, 31, 50, .06)`
    （現時点で同値。役割が違うので別名にしておき、片方だけ調整できるようにする）
- **`.card` にインラインで padding / background / border を書かない**（`index.css` の
  名指しの禁止。D-9 で `.card-tight-top` を足したのと同じく、必要ならクラスを足す）

## 4. 日付を押すと開く（本人指示）

- **既定は閉じている。** カレンダーの日付を押すと、**カレンダーカードと「すべてのセッション」の間**に
  その日のセッションが開き、**下のカード（すべてのセッション・音の傾向）が下へ押し出される**
- **枠の高さの上限は 192px**（`MY_DATA_DAY_PANEL_MAX_H`）。4件目からは
  **枠の中でスクロール**（`overflow-y: auto`）

  **【2026/08/26 訂正・統括の書き間違い】** ここは初版で「3件ぶん（64px × 3 = 192px）」と
  書いていたが、**1件の実寸は 64px ではなく 55px**（`.rowcard` 47px + 下の余白 8px。
  375×812 の Browser pane 実測）。したがって 192px は **3件ぶん（165px）ではなく、
  3件 + 4件目の頭 27px**（192 − 55×3 = 27）が見える高さである。

  **本人裁定で挙動は「このまま」**（2026/08/26）。訂正するのはこの記述だけで、
  `MY_DATA_DAY_PANEL_MAX_H = 192` も正典 `S1open.dc.html` の `max-height` も動かさない。
  **4件目の頭が覗くのは意図**である ── 枠がちょうど3件で切れていると
  「3件しかない」のか「まだ続く」のかが分からない。切れた4件目が
  「下にまだある（スクロールできる）」ことを、件数の行を置かずに伝えている
  （本人「件数でたところでなにも有意義な情報ではない」§3）。
- **動き**: 高さ 0 → 実寸 / **200ms / ease-out**。閉じるときは逆。
  `prefers-reduced-motion: reduce` のときは動かさず即座に切り替える（§6.1.5 の趣旨）
- **閉じる操作**（統括の判断 ─ §8 の(3)）:
  1. 同じ日付をもう一度押す
  2. 別の日付を押す → **その日に切り替わる**（閉じない）
  3. **開いている間、My Data の他の場所をタップする**（カレンダーのマスと、開いた枠の中を除く）
- その日の記録が 0 件の日は**押しても開かない**（押せない選択肢を出さない。F-77）

### 7.1 軸の行は「ラベルを値の上に積む」3カラムの等幅グリッド（2026/08/26・D-10c。本人裁定・凍結）

本人の言葉:

> ラベルを値の上に積む

`縦軸 音名 ▾` と1行に並べる形（`PlainSelect` の `inline`）を**やめ**、
**ラベルが上・値が下**の縦積み（`caption` の枝）へ戻す。
狙いは、値に列の幅をまるごと使わせて**長い選択肢を見分けられるようにする**こと。

| | 値 |
|---|---|
| 器 | `display: grid` / `grid-template-columns: 1fr 1fr 1fr` / `gap: var(--sp-2)`（8px） |
| セル | `min-width: 0`（grid の `1fr` ＝ `minmax(auto, 1fr)` の自動最小を外す。無いと長い綴りの列だけ広がる） |
| 1つの高さ | `var(--tap-min)`（**44px**）。§5 の例外ではなくなった |
| ラベル | 10px / `--c-ink-3` |
| 値 | 12px / 600 / `--c-ink` / `white-space: nowrap` / `text-overflow: ellipsis` |
| 列の境界 | **罫を引かない**（本人「むやみに線をひくのやめて」） |
| 位置 | **条件チップの行と同じカードの中の2行目**（カードは分けない） |

- 行は 30 → 44px（**+14px**。変更後の操作カードは **106px 実測**で、変更前は 30+30+`--sp-4` 16×2 = **92px**）。
  そのかわり **44pt に満たない例外が1つ減る**（残るのは「式の行」と「条件チップの行」）
- `ANALYSIS_ROW_H`（30）は**条件チップの行が引き続き使う**ので残す。
  ただし**軸の行は読まない**（行の器は高さを持たず、高さは中の 44pt が決める）
- `PlainSelect` の `inline` / `grow` と定数 `ANALYSIS_AXIS_MIN_W` は**定義ごと撤去**した
  （呼び手ゼロの分岐・定数を残さない）

**実測（375×812・Browser pane）**: 列 **99.66 / 99.67 / 99.66 × 44**、
行は 315px で `scrollWidth − clientWidth = 0`。
縦軸12 × 横軸7 × 分析軸13 ＝ **1092組**の走査で、はみ出し **0組** /
値が `…` だけの組 **0組** / 1文字も切れない組 **780/1092**。
切れるのは**横軸に `倍音強度(低次1-4)` / `倍音強度(高次5-8)` を選んだときだけ**で、
その場合も `倍音強度(低…` / `倍音強度(高…` と **6文字目まで出る**（低 / 高 は読める）。
縦軸・分析軸の綴りは**1092組すべてで1文字も切れない**。
詳細と限界は `DESIGN-SYSTEM.md` §5.2 の表を見ること。

---

#### （失敗の記録）下限 `ANALYSIS_AXIS_MIN_W = 87` は撤回した

D-10b は「軸の行の3つのアイテムは、それぞれ 87px より狭くならない」を凍結し、
`PlainSelect` の `inline` の枝の `min-width` に 87 を置いた。**これは間違った直し方だった。**

**何を見落としていたか**: **CSS の `min-width` は無条件の床**である。
「行が溢れそうなときだけ効く」ものではなく、**自然幅が 87px に満たないアイテムを
87px まで押し広げる**。つまり、幅が余っていた組にまで不足を作る。

**審査役の A/B 実測**（同一ページ・同一データ・`min-width: 0 !important` を注入して比較）:

| | 縦軸 | 横軸 | 分析軸 | 3つとも全部出るか |
|---|---|---|---|---|
| 下限なし | 63.77 | 112.45 | 118.78 | **出る** |
| 下限あり（87） | 87.00 | 105.84 | 102.16 | **横軸・分析軸が切れる** |

縦軸は 23.23px の空白を抱え込み、その分を横軸・分析軸から奪っていた。
30組の走査では、1文字も切れない組が **18/30 → 4/30**（**14組が悪化**）。
正典 A1 の 10px 等間隔のリズムも崩れていた（縦軸と横軸の見た目の間隔が 33.23px）。

**初版の §7.1 が書いていた論証も成立していなかった**（審査役の指摘）:

> 3つとも下限まで縮んでも行に収まるので、**縮む順が逆転しても優先順位の逆転は起きない**

これは**幅の話から「読める文字」の話を導いている**。行に収まることは
「どの綴りが何文字読めるか」を何も保証しない。**下限という発想そのものを捨てて**、
3列を等幅にすることで幅の取り合いを構造ごと無くしたのが D-10c である。

**残しておく教訓**: 「flex の縮み順」も「下限」も、**行の中で幅を配分する規則**であって、
画面に何文字出るかは決められない。読めるかどうかは**実測でしか出ない**。
