### 1.1 0 の目盛を「寄せない」— 初版の欠陥と訂正
初版は「**いちばん 0 に近い目盛を 0 ちょうどへ寄せる**」形にしていたが、
`lo = -1 / hi = 9` では**左端の目盛が -1 なのに「0」と表示される**（軸の端の値を偽る）。
0 の線は目盛とは**別に**引き、ラベルが重なる目盛を1つだけ譲る（`pivotCrowdedTickIndex`、
しきい値 `PIVOT_TICK_MIN_GAP_PX = 18`）。**0 のラベルは必ず出す。**

## 2. 操作部

### 2.1 条件のチップ行
`条件` のラベル ＋ 適用中フィルタのチップ ＋ 追加用の `＋`（破線）。

- チップ: 地 `--c-accent-tint` ／ 文字 `--c-accent` ／ 11px・600 ／ 角丸 `--r-sm` ／ 余白 `4px 9px`
  （正典の `#E4EAF2` / `#1D4E89` / `7px` の写像）。**枠は透明で場所だけ残す**
- `＋`: **破線の枠だけ**（地は持たない）。芯1「同じ物に枠線と違う地を両方与えない」
- チップの文字は `pivotFilterChipText` の1箇所（値の畳み方を2箇所に書かない）。
  値を選んでいない条件は次元名だけ、選んでいれば値そのもの、多すぎれば「他n」に畳む

**機能は1つも落とさない。** 正典は条件を1行に畳んでいるが、現行の編集UI
（12次元・値チップ・音域帯まとめ選択・日付/日数範囲・条件の削除）は**チップか「＋」を押すと下に開く**。
既定は畳んだ状態（`filterEditorOpen`）。

### 2.2 3カラムのセレクタカード
`並べる軸` / `数値` / `分け方`。中身は N-9 の `縦軸` / `横軸` / `指標` と**同じ状態**
（`pivotRow` / `pivotMetric` / `pivotCol`）で、正典に合わせて**名前だけ**を変えた。

- 器は `.surf-sunk` の中の `.card`（地・角丸・padding は作法が持つ。インラインで書かない）
- `grid-template-columns: 1fr 1fr 1fr` / `gap: var(--sp-2)`（正典の `8px`）。**【便CL 2026-10-11】縦軸と横軸の間に ⇄ の列（28px）を足して `1fr 28px 1fr 1fr` になった（§6.2）**
- **中央の列だけ左右に罫**（正典どおり。列の境界を余白ではなく線で示す）
- 部品は共有の `PlainSelect`（素のテキスト ＋ ▾）。`strong` を足して値だけ 600 にする
  （正典の 13px/600。**既定 false なので既存の呼び出しは 1px も変わらない**）
- 旧 `select.pivot-axis-select` は**規則ごと削除**（読み手ゼロ）

## 6. 【便CL 2026-10-11 本人裁定】縦軸・横軸の同じ一覧・⇄・散布図・秒・問い

**呼び名は「抽出条件 / 縦軸 / 横軸 / 分析軸」のまま。** 7指標・12次元・抽出条件・分析軸（系列6本まで）・

### 6.1 縦軸と横軸は同じ一覧
- シートの中は2つのまとまり: **「数値」**（`PIVOT_MEASURES` の7つ）→ **「項目」**（`PIVOT_DIMENSIONS` の12）。
  見出しは「数値」「項目」だけ。押せない理由の説明文は出さない（見ればわかる）。項目は2列。
  読み上げはまとまりごとに `role="group"`＋`aria-label`（「数値」「項目」。見出しの字は読み上げから外す）。
- 決まり: **項目は縦横どちらか一方だけ**（もう一方が項目なら、こちらの項目は全部 薄く .35・押せない）。
  **もう一方で選ばれているものも** 薄く・押せない。
- 状態は縦 `v`・横 `h` の鍵の組1つ（`pivotAxes`）。押せない行はもう一方の鍵から毎回導く（`pivotAxisOptions`）。
  以前の `pivotRow`（項目の側）/ `pivotMetric`（数値の側）はここから導く（`pivotAxesShape`）ので、
  項目 × 数値の集計 `buildPivot` は向きが変わっても同じ。設定は保存しない（メモリの上だけ ── F-59）ので、
  古い形を読み直す経路は持たない（審査の差し戻しで削除）。
- 既定は今のまま: 縦＝音名・横＝音程(¢)・分析軸＝リードメーカー。

### 6.2 ⇄（縦軸と横軸を入れ替える）
- **軸の行の専用の細い列**に置く（【2026-10-11 統括の決定・再審査】）。軸の行は **縦軸 | ⇄ | 横軸 | 分析軸** の4列のグリッド
  （`grid-template-columns: 1fr 28px 1fr 1fr`・`gap: --sp-2`）。⇄ の列の幅 28px は統括の決定。
  列を足して削る幅（28 + 溝 8 = 36px）は3つのセルで等しく分け合う（1つあたり約12px）ので、**3つのセルは等幅のまま、
  値に列の幅をまるごと使わせる D-10c を保つ**。
- 見た目は **24px の輪郭だけの円**（枠 `--c-line-strong`・地 `--c-surface`・字 `--c-ink-2`）。名前は「縦軸と横軸を入れ替える」。
  いつでも押せる（決まりが縦横で対称なので入れ替えた組も必ず有効）。円の縦の位置は**値の行**に合わせる（モックの「縦軸と横軸の間」。
  値の行の高さは書体で端末ごとに違うので、描いたあとに縦軸のセルの値の行を測る）。
- **当たり判定は ⇄ の列＋左右の溝**（列のセルに絶対配置で left / right を −`--sp-2`）。幅 28 + 8 + 8 = 44（`--tap-min` 以上）・高さは行いっぱい（セルの 44pt）。
  溝の端までなので、縦軸・横軸のどちらのセルの値や ▾ にも掛からない。375 幅で elementFromPoint を当て、「＋」・値の行・▾・
  縦軸 / 横軸のセルのどれとも重ならないことを実測した（重なり 0 点）。
- 375 幅で値が「…」で切れるのは（各セル 87.7px）: 倍音強度(低次1-4)（+33px）・倍音強度(高次5-8)（+34px）・リードメーカー（+4px）・
  リード主観評価（+6px）の4つ（縦軸・横軸。分析軸は数値を取らないのでリードメーカー・リード主観評価の2つ）。直す前（3カラム・各 99.7px）は
  倍音強度の2つだけだった。
- 【経緯】初版は縦軸のラベル行の右端に重ね、当たり判定が真上の「＋」と値の行・▾ を取った。2版は縦軸の値の右を 36px 空けたが、
  縦軸の値が19のうち13で切れて D-10c に反した。どちらも差し戻しで撤去し、PlainSelect に足した受け口（ラベル行の高さ・右の空き）も外した。
- 状態を持たない輪郭の円なので、DESIGN-SYSTEM の芯2（枠を持つ操作は状態を持つ）の**名指しの例外**（テンポの ± と同じ扱い。pitch-test が件数1で固定。
  DESIGN-SYSTEM「意図した例外」9）。

### 6.3 グラフは組み合わせで決まる
| 縦 × 横 | グラフ | 寸法 |
|---|---|---|
| 項目 × 数値 | 今の折れ線（縦＝項目）。**各行の右に秒数**（`--c-ink-3`。読ませる字なので ink-4 は使わない ── DESIGN-SYSTEM §1.1） | §1 の実数のまま |
| 数値 × 項目 | **横＝項目・縦＝値の折れ線**（`PivotLineChart catAxis="h"`）。項目名と秒数を下に2行。詰まるときは**名前と秒数を同じ列で**1つおき・2つおき…に間引く（`reedScoreLabelStep`） | 目盛5・点 r2.8＋白フチ1.1・縞（音名のときだけ）・系列の色と線種は §1 と共通。作図域の高さは My Data の音名グラフと同じ `CHART_PLOT_H_MY_DATA` |
| 数値 × 数値 | **散布図**（`PivotScatterChart`）＋幅ごとの平均の線 | 下の 6.4 |

**20秒未満の点は opacity .4**（`PIVOT_FEW_OPACITY`）。判定は**その点の系列のその項目の秒**（項目の合計ではない。表示と同じ丸めた秒）。
行・列に添える秒は系列を足した項目の秒。

### 6.4 散布図
- 目盛・0 の線・ラベルは SVG、**点は canvas**（devicePixelRatio 対応）、平均の線と点はその上に重ねた SVG。
- 点は **1.8px の正方形を間引かずに全部**。濃さ alpha = min(.25, 9/√点数)。
- 色は系列の色（`SERIES_STYLES`）。canvas は var() を読めないので **描くときに :root の計算値を getComputedStyle で読む**（色を手で写さない）。
  アプリにはダークのトークンが無いので、テーマの変化を見張って描き直す仕掛けは持たない（審査の差し戻しで削除）。
- 範囲は縦横とも **0.5〜99.5 パーセンタイル**（外れ値で潰れない）に、折れ線と同じ 12% の余白。音程(¢)の軸は 0 を必ず含める。
- 平均の線: 横軸の値を一定の幅ごとに縦軸の値を平均（**clarity 重み付き** ＝ 折れ線と同じ）。**20点（2秒）以上ある幅だけを結び**、足りない幅・点の無い幅で線を切る。
  各幅の平均の位置に r2.8 の点。点の位置は**その幅の点の重み付き平均**（横も縦も）。幅の中央に置くと、値が幅の端に偏ったデータで
  点が作図域の外へ出るため（実測: 音量が -28.0 ちょうどの点だけの幅の中央 -27.5 は範囲の外だった）。幅の表（`PIVOT_SCATTER_BIN_W`）:

  | 横軸 | 幅 | 根拠 |
  |---|---|---|
  | 音量 | 1dB | 本人裁定 |
  | 音程 | 2¢ | モック |
  | HNR | 1dB | モック |
  | 重心 | 50Hz | モック |
  | ピッチ | 5Hz | 半音の幅は最も低い音域（約140Hz）で約8Hz。5Hz なら隣の半音と同じ幅に混ざらない |
  | 倍音強度（低次・高次） | 0.02 | 値は 0〜1（画面は ×100）。画面の 2 ＝ モックの「倍音 2」 |
- **ゲート: 点も今の集計と同じゲートを通す**（音程(¢)は `selectPitchAggregationFrames`、倍音・HNR・重心は `timbreSustained`）。
  縦と横で違うゲートなら**両方を通ったフレームだけ**。抽出条件の判定は `buildPivot` と同じ式（`pivotActiveFilters` / `pivotFrameRejected` を共有）。
- 凡例に系列ごとの秒数（`--c-ink-3`）、右端に「縦 単位 · 横 単位」。
- 空のときの文言は「…ここに**点**が育ちます」（折れ線のときは今のまま「…ここに折れ線が育ちます」）。

### 6.5 秒
件数は**秒**（フレーム数 × 0.1秒 を整数に丸め、3桁区切り。`groupDigits`）。全部のグラフの下に**合計の秒**（例「412秒」・`--c-ink-3`）。
データが無いときは合計の秒を出さない。合計には表示していない系列（7本目以降）も含む。
音量は dBFS のまま。段・「大きい / 小さい」などの区切りの名前は出さない。

### 6.6 問い
セレクタのカードの上に、横にスクロールする1行のピル（`data-noswipe`・当たり判定 `--tap-min`）。押すと縦軸・横軸・分析軸を一度に書く（抽出条件は触らない）。
今の組と一致するピルを強調する（別の状態を持たない）。見た目: 地 `--c-surface`・枠 `--c-line-strong` / 選択中は地 `--c-accent`・字 `--c-on-accent`（枠は透明＝芯1）。
文字・余白・角丸は条件のチップと同じ（12px・600 / 4px 11px / `--r-pill`）。問いの表は `PIVOT_QUESTIONS` の1か所:

| 問い | 縦 | 横 | 分析軸 |
|---|---|---|---|
| 音程の癖は? | 音名 | 音程(¢) | なし |
| 音量で音程は変わる? | 音程(¢) | 音量(dB) | なし |
| 音量で音色は変わる? | HNR | 音量(dB) | なし |
| リードで音程は変わる? | 音名 | 音程(¢) | リード(個体) |
| リードで音色は違う? | 音名 | HNR | リード(個体) |
