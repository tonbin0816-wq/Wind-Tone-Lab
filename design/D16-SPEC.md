# D-16 凍結仕様 ― 折れ線を「線 + 面」へ（案4）

**出どころ**: 本人の実機フィードバック第7陣。
> やっぱり折れ線グラフのエリアのデザインが気に食わない、、**音の数が多いので点の数が多くて気持ち悪い**のかも。
> **線の色もあんまりセンスがないか**、、？ / なんかスマートさにかけるんだよな、、うまく言語化できない

7案を実寸モックで提示（https://claude.ai/code/artifact/1b6b40c9-2ea7-46f0-ae8f-b9241e97b295 ）し、
**本人が案4を採用**（2026/08/28）。

## §0 なぜ案4か（次に触る人へ）

不満は3つあり、**別々の原因**だった。測った値:

| 症状 | 実測 | 原因 |
|---|---|---|
| 点が気持ち悪い | 点 **59個** / 直径 **4.93px** / 間隔 **8.22px** / 線 **2px** | **点の直径が線の 2.5倍**あり、間隔に対して隙間より玉が目立つ。線が「流れ」でなく「玉をつなぐ紐」に見える |
| 線の色にセンスがない | `#174585` と `#7FA0CE` | **色相がほぼ同じ（216°）で明度だけ違う**。2本が「別のもの」でなく「同じものの濃い方と薄い方」に見える |
| スマートさに欠ける | その日の線が **7本の断片**（4/1/1/3/10/4/3点。**1点だけの断片が2つ**） | 吹いていない音で切れる。**59個の玉 + 7つの破片**が同じ面に乗っている |

**案3（飛び飛び＝点 / 連続＝線）は本人が却下**した。理由が正しい:
> その日は点だけでもいいかも知れんが、**目安vs自分の平均とかだと点の数は相変わらず沢山出る**ことになるよなあ

案4 は **面と線という「形の種類」で2本を分ける**ので、
- **どの組み合わせでも点が1つも出ない**（目安 × my平均 でも増えない）
- **色相を離す必要が無い**（形が違えば混ざらない）ので、体系に新しい色を増やさずに済む
- 断片が7本に割れることは**線が途切れること自体で伝わる**

3つの症状が1手で解ける。

## §1 描き方（凍結値）

| 要素 | 値 |
|---|---|
| **1本目（左）** | **線のみ**。太さ **2.4px**、色 `--c-accent`。`stroke-linejoin/linecap: round` |
| **2本目（右）** | **面 + 細い線**。線は太さ **1.6px**、色 `--c-accent-mid` |
| **面** | `--c-accent-mid` の **不透明度 0.28**。トークンとして定義し、**インラインで rgba を散らさない** |
| **点（`<circle>`）** | **両方とも描かない。撤去** |

## §2 面の下端は「中央線」

面は **中央線（D-9 §8 の `centerAt`）を底**にして塗る。値が中央より上なら上向き、下なら下向きの面になる。

**0 で固定しない。** 平均差分は中央 = 0 だが、HNR / 重心 / 音量は**その指標で描いている全値の平均**が中央（D-9 §8）。
面の底をそこに合わせないと、「中央線からどれだけ離れているか」という画面の読み方と食い違う。

## §3 描画の順（重なりの裁定）

**下から: 面 → 目盛の罫 → 中央線 → 2本目の線 → 1本目の線。**

- **中央線は面の上**。不透明度 0.28 の面に沈むと、§2 で面の底に選んだ基準が読めなくなる
- **1本目がいちばん上**。飛び飛びの側が「図」、連続の側が「地」という役割分担が案4 の芯

## §4 面と線の割り当ては「側」で決める（連続性で決めない）

**2本目（右）が面、1本目（左）が線。** データが連続かどうかでは決めない。

理由: D-14 で**左右は自動で入れ替わる**ようになった。連続性で決めると、入れ替えたときに
「どちらが面になるか」がデータ次第で変わり、**同じ操作の結果が予測できなくなる**。
側で固定すれば、入れ替えれば見た目も入れ替わる ── 操作と結果が1対1で対応する。

**目安 × my平均 のように両方が連続でも、規則は同じ**（右が面）。

## §5 窓型（マトリクス）には触らない

案4 は**折れ線だけ**の話。窓型の見せ方は D-9 §4 のまま1pxも変えない。

## §6 波及

- **点を撤去したことで読み手ゼロになる定義**（点の半径の定数など）は**定義ごと削除**する
- **他の3画面（リード比較 / セッション詳細 / リード個体詳細）にも同じ `NoteAxisLineChart` が使われている。**
  D-9 は**ここで退行を出した**（D-12 で修正）。**面を出すのは My Data だけか、他画面にも広げるかを必ず判断し、
  判断したことを明記する**。統括の既定は「**My Data だけ**」── 他画面は D-8 からの見た目を保つ
- `design/DESIGN-SYSTEM.md` に**面のトークンと不透明度**を書く。**測った範囲と、測っていないことを書き分ける**

## §7 検査で守れること / 守れないこと

**守れる**:
- 点（`<circle>`）を1つも描かないこと
- 面の底が中央線の値であること（`centerAt` から出ていること）
- 描画の順（面が中央線より下、1本目が最上）
- 太さ 2.4 / 1.6 と不透明度 0.28 が**正典から読めている**こと
- **他画面に面を出していないこと**（D-9 の退行と同じ型を二度やらないため。§6 の判断に合わせる）

**守れない（実機待ち）**:
- 不透明度 0.28 の面が**実機の画面で見えるか / 濃すぎないか**。Chrome の実測を合格根拠にしない（罠15）
- 「スマートに見えるか」そのもの
