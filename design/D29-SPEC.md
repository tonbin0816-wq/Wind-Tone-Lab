## §1 個別セッション ── 案A「素直に移す」

### 1.1 やること

`src/App.jsx` の `AnalysisLabView` 内、セッション詳細の `return`（`:14324` 付近）:

```jsx
<div className="surf-rule">     ←  "surf-card" へ
  <SwipeBackArea …><SessionDetailView …/></SwipeBackArea>
```

**これだけで中の `.card` 3枚（指標グラフ / 録音 / メモ）が白いカードになる。**
見出し（`DetailHeader`）は `.card` の外にあるので、**そのまま沈めた地の上に載る**（案A の姿）。

### 1.2 確かめること

- `.card` が **3枚**（`MetricTabCard` が自分で1枚持つ／録音／メモ）
- **横スクロールが出ないこと。** 罫の作法では `.card` の左右 padding が 0、
  カードの作法では 16。中で左右いっぱいに伸びている物があると、そのぶんはみ出す
  （D-7 でカレンダーの grid が実際にこれで壊れた）
- 指標のタブ行は `marginLeft: -halfGap`（当たり判定を広げる既存の手）を持つ。
  カードの padding が付くぶん**開始位置が 8px 内側へ動く**が、これは作法どおりで正しい

## §2 個別リード ── 案G「点数を小カード3枚に」

### 2.1 面の名乗りを付け替える（**ここが今回いちばん壊れやすい**）

いまリードタブは**根が1つの `.surf-rule`**（`src/App.jsx:3993` 付近）で、
**Top（登録 / 比較）も個体詳細も一緒に包んでいる**。ここを裏返すと
**本人が名指しで除外した「リードタブ Top」まで裏返る**。

**§6.6 が既に書いている手をそのまま使う**（新しい形を発明しない）:

> データタブは根に作法のクラスを置かず、**3つの `return` がそれぞれ名乗る**

- **`topTab === "reeds"` の包み（`:3993`）から `className="surf-rule"` を外す**
- `ReedsTab` の**2つの `return` がそれぞれ名乗る**:
  - 個体詳細（`if (evaluatingReed)` の `return`。`:9824` 付近）→ **`.surf-card`**
  - Top（登録 / 比較 の `return`。`:9838` 付近）→ **`.surf-rule`**（いまと同じ見た目）

**`.surf-card` と `.surf-rule` を入れ子にしないこと。** §6.6 が
「同じ詳細度同士のカスケードになり、どちらが勝つかが `index.css` の行の順序に依存する
= いちばん壊れやすい形」と名指ししている。

### 2.2 点数の行を小カード3枚にする

いまは `ReedScoreField` が **1つの `<button>`**（`aria-label="総評・厚さ・バランスを編集"`）で、
中に3つの区画（**数字が上・ラベルが下**）を持ち、行の下に `borderBottom` の罫が1本ある。

**変えること**:
- 3つの区画を **`.rowcard` 3枚の横並び**にする。間は **8px**
- 行の **`borderBottom` は外す**（カードの作法は**罫を1本も引かない**）
- メモ（`MemoField`）は**独立した `.card`** へ出す

**変えないこと**:
- **数字が上・ラベルが下の順番。** モック（`detail-card-proposals.html` 案G）は
  ラベルを上に描いているが、**あれは統括の作画ミスであって提案ではない**。
  今回はカード化だけなので**現状の順番を保つ**
- 数字の大きさ `--fs-2xl` / 書体 `--font-num` / 太さ 600 / 未評価のときの色 `--c-ink-3`・
  評価済みの `--c-accent`（`it.rated` の分岐）
- ラベルの `--fs-xs` / `--c-ink-3`

### 2.3 押したときの挙動（**§6.4 を保つ**）

**3枚のどれを押しても、いまと同じ3列ダイヤルが1回で開く。**

- **項目ごとにフォーカスさせない**（「厚さを押したら厚さの列が選ばれている」等は**やらない**）。
  それは別の変更で、この周の指示に入っていない
- 当たり判定は3枚とも **44px 以上**
- 読み上げのラベルは、いまの `総評・厚さ・バランスを編集` が
  **どのカードを押しても同じ物が開く**ことを伝える形であること

### 2.4 `.rowcard` の寸法を**インラインで上書きしない**

§6.6 が名指しで禁じている:

> 小さいカードを `.card` と同じクラスにしない。寸法が2つになると、どちらかを
> インラインの `padding` で上書きすることになり、**その要素だけ作法から外れる**

`.rowcard` は `padding: 10px 14px` / 角丸 `--r-md` / `--shadow-row`。
375px なら 1枚あたり **(375 − 14×2 − 8×2) ÷ 3 = 110.3px**、内側は 82px。
「バランス」（`--fs-xs` = 12px・4文字）は入る見込みだが、**入らなかったら手を止めて報告すること**。
勝手に padding を詰めたり文字を小さくしたりしない（新しい寸法を作らない）。

## §5 検査で守れること / 守れないこと

**守れる**:
- 2画面が **`.surf-card` を名乗り、`.surf-rule` と入れ子になっていない**こと
- **リードタブ Top が `.surf-rule` のままである**こと（裏返っていない）
- 点数が **`.rowcard` 3枚**で、**`padding` をインラインで上書きしていない**こと
- 点数の行に **罫（`borderBottom`）が無い**こと
- **どのカードを押しても同じ1つの口（3列ダイヤル）が開く**こと
- 当たり判定が 44px 以上・横スクロールが出ないこと
- **計測タブ Top / リードタブ Top / すべてのセッション / 計測タブ詳細が1px も動いていない**こと
  （罠16: **変更前も同じ手順で測る**）

**守れない（実機待ち。罠15）**:
- **地とカードの差の見え方。** ΔL\* は 2.79 しかなく、Chrome と iPhone で見え方が変わる
- **本人の実データでの縦の長さ。** セッション数の多いリードでは推移のグラフが密になる
- **スクロールの感触**（影のぶん下へ流れる勢いが弱く感じられることがある）
