## §1 クリック音 ── 4種から選ぶ

### 1.1 いまの音（変えずに残す）

`getMetroClickBuffer`（`src/App.jsx:4491`）＋ `scheduleMetroClick`（`:4530` 付近）:
- 60ms のノイズ、`exp(-i/(n*0.15))`（≒9ms）で減衰
- バンドパス **Q=1.6**、中心 accent 2900 / beat 2000 / 分割 1300 Hz
- ゲインは `vol` から 60ms かけて指数で 0.0001 へ（**バッファ自身の減衰と二重**）
- 音量 accent 1.0 / beat 0.85 / 分割 0.6

**この音は「現行」として選択肢に残す。** 本人が A/B できないと良し悪しを判断できない。

### 1.2 足す3種（**音の設計は実装が決めてよい。狙いだけ凍結する**）

| 名前 | 狙い | 手がかり |
|---|---|---|
| **木** | 本物のメトロノームに近い、芯のあるコツッという音 | Q を上げて音程感を出す。減衰を短く |
| **電子** | いちばん**埋もれない**。サックスの倍音と重ならない帯域で明確に鳴る | 純音系。倍音が少ないぶん楽器と混ざらない |
| **鋭いクリック** | いちばん短い。**音として聞くより「点」として感じる**もの | 極短。高域寄り |

**条件**:
- 4種とも **accent / beat / 分割** の3段を持つ。段の付け方（音程差か音量差か）は音ごとに決めてよい
- **既存の3段の音量差（1.0 / 0.85 / 0.6）を出発点にする**。変えるなら理由を書く
- **新しい定数を体系に増やさない。** 音の定数はクリック音の定義に閉じる（`DESIGN-SYSTEM.md` の値ではない）
- **「良い音」は実装が判定しない。** 本人が実機で聴いて決める。報告に「良くなった」と書かないこと

### 1.3 「今のクリック音の向上」について

**現行を書き換えない。** 改善版は**4種のうちの1つ**として並べ、本人が A/B したうえで
「これを既定にする」と決めたときに初めて既定を動かす。

理由: 音は Chrome では判定できず、実装も統括も良し悪しを決められない。
**既存の音をいきなり差し替えると、悪くなったときに戻す基準が消える。**

### 1.4 選び方と保存

- **テンポ拍子シート**（`F-91` で作った、拍子表示・拍の●から開くもの）の中に置く
- **選んだ音は保存する**（アプリの既存の保存の作法に従う。新しい保存先を発明しない）
- **押した瞬間に音が鳴って確かめられる**こと（メトロノームが止まっていても）
- 既定は**現行**（本人が決めるまで変えない）

### 1.5 触ってはいけないもの

- **クリックがマイクへ回り込むぶんの除外**（`isNearScheduledClick` / `scheduledClicksRef`、
  `App.jsx:3321` 付近）。**音を変えると回り込みの見え方が変わる**ので、
  除外の窓（前30ms〜後90ms）は**動かさない**。動かす必要が出たら手を止めて報告
- マスターの `gain 2.6` とリミッター（`getMetroMasterInput`）。**音量の調整は今回やらない**
  （口コミでは音量の不満が7件あるが、本人の指示に入っていない。別途起票する）
- メトロノームのスケジューリング（`LOOKAHEAD` / `setInterval(25)`）。**予約の仕組みは1文字も変えない**

## §2 タップテンポ

### 2.1 置き場所

**テンポ拍子シートの中**（テンポの −/♩=n/＋ と同じ行か、その直下）。
**普段の画面に部品を増やさない**（計測タブの画面は「読む物」で、押す物を足すと当たり判定が争う）。

### 2.2 決め方（凍結）

- **直近4つの間隔の中央値**からテンポを出す（平均ではない ── 1回のミスタップで壊れないため）
- **2秒**あいだ叩かれなければ、それまでの間隔を捨てて測り直す
- 出たテンポは **`clampMetroTempo`** を通す（範囲の唯一の答えはこの関数。**直書きしない**）
- **2回目のタップから**テンポが出る（1回では間隔が無い）

### 2.3 反応（口コミの指摘への対応）

> 「タップから少し遅れて音が出るので、望むテンポをタップし辛い」

- **押した瞬間に見た目が返る**こと。音を待たせない
- **叩いている最中にメトロノームが鳴っていてもよいが、タップの判定は音の予約に依存しない**
  （`performance.now()` を使う。`ctx.currentTime` の量子化（実測 5.33〜10.67ms）を挟まない）
- **何回叩けたか**が見えること（1回目なのか、もう出ているのか）

### 2.4 触ってはいけないもの

- テンポの範囲（`clampMetroTempo`）・拍子・分割の仕組み
- メトロノームが鳴っている最中にテンポを変えたときの挙動（既存のまま）

## §3 検査で守れること / 守れないこと

**守れる**:
- 4種が定義され、**選んだものが保存され、読み直しても残る**こと
- **現行の音の定数が1つも変わっていない**こと（1.3。ここが崩れると A/B の基準が消える）
- 回り込みの除外の窓が動いていないこと
- タップテンポ: 中央値であること / 2秒で捨てること / `clampMetroTempo` を通ること /
  2回目から出ること / 1回のミスタップで壊れないこと（**純関数に切り出して数値で確かめる**）

**守れない（実機待ち）**:
- **どの音が良いか。** Chrome では鳴らして判定できない
- タップの叩き心地
