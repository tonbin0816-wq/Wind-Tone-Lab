## 2. マトリクスカード

### 2.1 器
`.surf-sunk` の中の `.card`（＝地 `--c-sunk` / 角丸 `--r-md` / padding `--sp-4`）。
**インライン style で background / border / padding を書かない**（作法が丸ごと死ぬ。index.css の警告）。

見出し行: 左に見出し（`--fs-xs` / 600 / `--c-ink`）と、その下にサブ（10px / `--c-ink-3`）。
右端にそのマトリクスの**実測レンジ**（10px / `--font-num` / `--c-ink-3`）。

| カード | 見出し | サブ |
|---|---|---|
| 上 | `今日の自分` | `{日ラベル} − {比較対象名}` |
| 下 | `いつもの自分` | `{期間ラベル}の平均 − {比較対象名}` |

`{日ラベル}` は **`myDataTodayOrLatestFrames` の `label` をそのまま使う**（今日 / `8/15`）。
「今日」の綴りを2箇所に持たない。正典は `今日 −` 固定だが、**当日のデータが無い日に「今日」と
偽らない**という N8-SPEC 5 の規則が上位。

### 2.2 グリッド
- 列 = **12 の音名（ピッチクラス）**、行 = **オクターブ**
- 音名とオクターブは **`concertNoteLabelOf(semitoneIndex, saxType, tuningHz)` の戻り値を分解して作る**
  （実音ラベル。折れ線の軸と同じ1箇所から読む。新しい音名規則を作らない）
- **行（オクターブ）は固定しない。** 正典は 3/4/5 の3行だが、これは Alto のときの実際の音域。
  Tenor は1オクターブ下がるので**データから出てくるオクターブの集合**を昇順に並べる
  （罠4「箇所数の釘付け禁止」）
- **フラジオは含めない**（`noteAxisCount(saxType, false)`）。本人指示「mydata のカードの
  このグラフにはフラジオまで入れなくていい（他は入れる）」を、後継である
  このマトリクスがそのまま引き継ぐ
- セル: 高さ 26px / 角丸 `--r-xs` / gap 3px。**音域の外のセルは空**（地も文字も無し）
- 左に オクターブ番号の列（幅 11px / 10px / `--c-ink-3`）、上に音名ラベル行（10px / `--c-ink-3` / 中央）

### 2.3 値
セルの値 = **その音の {上段:その日 / 下段:期間平均} − {比較対象のその音の値}**。

| 指標 | 母集団の値 | 書式 |
|---|---|---|
| 平均差分 `pitchCentsSigned` | `groupFramesByNote` の `pitchCentsSigned` | `formatSignedCents`（0 に符号を付けない） |
| HNR `hnrDb` | 同 `hnrDb` | 符号付き整数 |
| 重心 `spectralCentroidHz` | 同 `centroidHz` | 符号付き整数 |
| 音量 `volumeDb` | 同 `volumeDb` | 符号付き整数 |

比較対象の値:

| 比較対象 | 値 | 出せる指標 |
|---|---|---|
| `自分の平均` | その音の**期間平均**（`groupFramesByNote(periodFrames)`） | 4指標すべて |
| `目安` | `getNoteIdeal(selectedIdeal, semitoneIndex)` の対応する量 | 4指標すべて |
| `±0` | 定数 0 | **平均差分のときだけ**（正典どおり） |

- **比較対象が読めない音（目安が無い / 期間平均が無い）はセルを空にする。** 0 で埋めない
- **目安が未設定のときは `目安` チップを出さない**（F-77 の罠: 押せない選択肢を出さない）

### 2.4 セルの文字サイズ 9.5px の根拠
375px 実機での**セルの内幅**:
`375 − page-side-pad 14×2 = 347` → カード padding `--sp-4` 16×2 → `315`
→ オクターブ列 11 + gap 5 → `299` → 12列 gap 3×11 = 33 → `266 / 12 = 22.17px`。
最長の値は重心の `−240` の4字。`--font-num` の tabular で 1字 ≒ 0.57em なので
9.5px なら 21.7px で収まり、10px では 22.8px で**溢れる**。
正典は 8.5px。**Browser pane で 4指標 × 3比較対象の全セルの実測 overflow が 0 であることを検査する**。

## 3. 発散カラースケール（この周で足す唯一の新しい値）

正典 README の8段をそのまま採る。**青＝比較対象より低い / 金＝比較対象より高い / 中央ほど淡い**。

```
--c-div-1 #43719F   --c-div-5 #E2D0A3
--c-div-2 #658BB1   --c-div-6 #D1B570
--c-div-3 #89A6C3   --c-div-7 #C39F45
--c-div-4 #B3C6D9   --c-div-8 #B5891C
```

**青の半分を既存の紺ランプ（`--c-accent`→`--c-accent-line`）で代用しない。**
`--c-accent` (#174585) は金の端 (#B5891C) より明度がずっと低く、
半分だけ差し替えると**発散スケールの左右の視覚的重みが釣り合わなくなる**（＝色が嘘をつく）。
機能色（`--c-good` / `--c-warn` / `--c-bad`）と同じ扱いで、装飾都合で変えない。

**段の決め方（純関数 `divergingStep(v, maxAbs)` → 1..8）**
- `maxAbs` = **そのマトリクスの実測の最大絶対値**（固定閾値ではない。正典の指定）
- `maxAbs <= 0` のとき: `v < 0 ? 4 : 5`
- それ以外: `t = clamp(v / maxAbs, -1, 1)` → `step = clamp(floor((t + 1) / 2 * 8), 0, 7) + 1`
- したがって `v = 0` は 5（金側のいちばん淡い段）、`v = -0` 未満は 4 に落ちる

**セルの文字色（純関数 `divergingInk(step)`）**
相対輝度が 0.5 未満の段（1・2・7・8）は `--c-on-accent`、それ以外は `--c-ink`。
（値の判定は実装で計算せず、**8段それぞれの答えを検査で固定する**）

**凡例**: カード2枚の**外側に1つだけ**。左右に方向ラベル（10px / `--c-ink-3`）、
中央に8段のバー（各 height 5px / gap 2px / 両端だけ角丸）。

方向ラベルは **4指標とも `低い` ← → `高い`** にする。
README は「指標によってラベルが変わる」と書いているが、**具体の語は取り込めなかった側
（256KiB で切れた `<script>`）にあり、正典から読めない**。
本人の既出の原則「このアプリの集計はデータの事実を提示するだけで解釈はユーザーに委ねたい」に
沿う語を選ぶ。**推測で「澄んだ」「明るい」等の解釈語を作らない。**
（実機で本人が語を指定したら差し替える。BACKLOG に起票する。）

## 4. 比較対象チップ

- ラベル `比較対象`（10px / `--c-ink-3`）＋ チップ列（gap `--sp-1`）
- チップ: 角丸 `--r-md` / `--fs-xs` / 600 / **`min-height: var(--tap-min)`**
  - 選択中: 地 `--c-accent` / 文字 `--c-on-accent` / 枠 `1px solid transparent`
  - 非選択: 地 `--c-sunk` / 文字 `--c-ink-2` / 枠 `1px solid var(--c-line)`
  - **枠は選択・非選択とも 1px 分の場所を確保する**（`transparent` で。F-75 の作法。
    枠を 0 にすると幅が 2px 動く）
- **上下2枚のマトリクスで比較対象は共通**（別々には選べない）
- `±0` は **`平均差分` タブのときだけ**列に増える
- 指標タブを平均差分以外へ動かしたとき、比較対象が `±0` だったら **`自分の平均` へ落とす**
  （存在しない選択が選ばれたまま残らない）
- 永続化しない（再マウントで `自分の平均` に戻る）

### 4.3 下のカードを畳む条件 — **正典の記述から意図的に外す**
README は「**`比較対象 = ±0` を選んだときのみ**、上のカードとの重複を避けて折りたたむ」と書いている。
**これは実装できない**（`±0` のとき 上＝その日の絶対値・下＝期間平均の絶対値 で、重複していない）。

実際に退化するのは **`比較対象 = 自分の平均`** のとき:
下のカードは `期間平均 − 期間平均` なので**全セルが構造的に 0** になる。
よって **`比較対象 = 自分の平均` のときだけ下のカードを出さない**。
正典の `sc-if value="{{ p9Open }}"` という条件付きの構造そのものは保つ。

## 6. 練習カード「この5週の練習」

- 器は `.surf-sunk .card`
- 見出し `この5週の練習`（`--fs-xs` / 600）＋ 右に合計時間（数字だけ 600 / `--font-num`、単位は素）
- 母集団は**マトリクスと同じ**（奏者=自分 ＋ 選択中の楽器種別）。**期間セレクタには従わない**
  （見出しが「この5週」と言い切っているため。窓は常に直近5週）
- 窓 = **今日を含む週の週末まで**の5週 × 7日 = 35マス。週の始まりは**月曜**（正典の曜日ヘッダが 月〜日）
- 暦日は **`localDayKey` だけ**で組み立てる（罠14。`toISOString` の UTC 暦日を使わない）
- セル: 高さ 34px / 角丸 `--r-sm` / gap 4px

**濃さ（`calendarLevel(minutes, maxMinutes)` → 0..4）**
- 記録が無い日 = 0 → `--c-sunk`
- あとは `t = minutes / maxMinutes` で 4段: `t<=.25` → 1 / `<=.5` → 2 / `<=.75` → 3 / それ以上 → 4
- 色は**既存の紺ランプをそのまま**: 1 `--c-accent-tint` / 2 `--c-accent-line` / 3 `--c-accent-mid` / 4 `--c-accent`
- `maxMinutes <= 0` のときは全て 0

**選択日**は枠で示す（`2px solid var(--c-ink)`）。`box-sizing: border-box` なのでマスは動かない。
既定の選択日 = **記録のある最新の日**（無ければ今日）。

**選択日のセッション一覧**（区切り線の下）
- `{M月D日} のセッション` （`--fs-xs` / 600）＋ 右に件数（11px / `--c-ink-3`）
- 行: 時刻（`--fs-sm`）／ その下にメタ（10px / `--c-ink-3` / `リード · 奏者` — 既存 `reedShortLabel` の綴り）
  ／ 右に長さ（`--fs-xs` / `--font-num`、既存 `sessionDurationLabel`）
- 行タップ → セッション詳細（既存 `onOpenSession`）
- **0件の日**は「この日の記録はありません」の1行

**最下行 `すべてのセッション {全件数} 件 ›`**（`--fs-xs` / `--c-accent` / `min-height: var(--tap-min)`）
→ **新しい全件一覧ページへ遷移**。

## 8. 検査（`scripts/pitch-test.mjs`）

**罠1「検査名は実際に検証している内容しか名乗らない」。罠2「純関数を守っても配線が無防備なら意味がない」。
罠3「期待値は正典か実装の外から読む」。**

必ず入れるもの:

1. `divergingStep` — 境界（`t=-1` / `0-` / `0` / `+1` / `maxAbs<=0`）を**値で**固定。
   8段すべてが到達可能であることも示す
2. `divergingInk` — 8段それぞれの答えを固定（実装と同じ式で書き直さない）
3. `calendarLevel` — 0..4 の境界を値で固定。`maxMinutes<=0` → 0
4. **8段の hex は `design/dc-mydata-redesign.html` の `#9b` 区画から読む**（`src/index.css` と突き合わせる）。
   実装の定数を実装の定数と比べる恒真検査にしない
5. **配線**: マトリクスの `<div>` に `divergingStep(...)` の呼び出しが**隣接して**いること、
   `includeAltissimo` 相当が `false` で渡っていること、
   比較対象が上下2枚に**同じ変数**から渡っていること
6. `±0` チップが `平均差分` 以外で**列から消える**こと（配線の綴りで固定）
7. 下のカードの条件が `自分の平均` であること（§4.3。**正典と違えた箇所なので特に固定する**）
8. `localDayKey` 以外の暦日の作り方（`toISOString().slice(0,10)`）がこの周の新規コードに無いこと

**Browser pane（375×812）の実測**:
- 4指標 × 3比較対象（=平均差分のみ ±0 を含む）の**全セルの overflow が 0**

  （`elementFromPoint` は**整数1px刻み**。罠10）

# 実装で確定したこと（凍結仕様からの差分・2026/08/22）

**凍結時の本文は書き換えていない。** 実装中に測って分かったこと・審査の芯とぶつかって
変えたことをここに追記する（「仕様と実装のどちらが正か」を後から追えるようにするため）。

## D1. 比較対象チップは A型（`.ctl-state`）にした — §4 の書き換え

§4 は「選択中＝地 `--c-accent` / 非選択＝地 `--c-sunk` ＋ 枠 `--c-line`」と書いていた（正典 `#9b` の写像）。
これは **index.css の芯1「同じ物に枠線と違う地を両方与えない」に正面から反する**（実際に
`scripts/pitch-test.mjs` の §17 が落ちた）。加えて体系では**紺の塗りは「主要動作の合図」に予約**
されている（`.ctl-danger` の解説）。

比較対象は**状態を持つ**もの（選択中が切り替わる）なので、体系の答えは **A型 `.ctl-state`**：
地は透明・枠は `--c-line-strong`・選択中だけ枠が `--c-accent`。角丸も地も枠もクラスが持つ。
本人の裁定「既存トークンへ寄せる」に従った結果で、**正典と意図的に違えた1点**。

## D2. セルの数字は4指標とも符号付き整数 — §2.3 の書き換え

§2.3 は平均差分だけ `formatSignedCents` と書いていたが、あれは**小数1桁**を返すので
`+12.3` は5字あり、セル内幅に入らない。**書式を指標ごとに分けない**（読み手が桁の意味を
取り違えない）ことを優先し、4指標とも `Math.round` の符号付き整数にした。
`0` と、0 に丸められる負の値には符号を付けない（`-0` を出さない）。

## D3. セルの 9.5px の根拠を実測で置き換えた — §2.4 の訂正

§2.4 は「セル内幅 22.17px / 送り幅は 1字 ≒ 0.57em」と**計算で**書いていた。
Browser pane 375×812 の**実測**：

| | 実測 |
|---|---|
| セル内幅 | **22.00px** |
| `-240` | 19.17px |
| `+240` / `+999` | **21.88px**（いちばん厳しい。余裕 **0.12px**） |
| `-88` | 14.05px |
| `+1200`（5字） | 26.98px → **溢れる** |

4字までは収まるが余裕は 0.12px しかない。5字は `overflow: hidden` が切る。
**色は切れない**ので「比較対象より高い/低い」の信号は必ず残る。
実機のフォントが少しでも広ければ `+NNN` は切れ得る — **実機で確認する項目**。

## D4. セルの文字色は 1段目だけ白 — §3 の訂正

§3 は「相対輝度 0.5 未満の段（1・2・7・8）を白」と書いていたが、**計算していない値だった**。
実際に相対輝度から出したコントラスト比：

| 段 | 白 | 濃(`--c-ink`) | 答え |
|---|---|---|---|
| 1 `#43719F` | **5.12** | 3.24 | 白 |
| 2 `#658BB1` | 3.57 | **4.64** | 濃 |
| 3 `#89A6C3` | 2.53 | **6.55** | 濃 |
| 4 `#B3C6D9` | 1.75 | **9.46** | 濃 |
| 5 `#E2D0A3` | 1.52 | **10.87** | 濃 |
| 6 `#D1B570` | 1.99 | **8.33** | 濃 |
| 7 `#C39F45` | 2.51 | **6.60** | 濃 |
| 8 `#B5891C` | 3.20 | **5.17** | 濃 |

**白が勝つのは 1段目だけ。** 左右の端で答えが揃わないのは2つの端の明度が違うからで、
揃えると片方が読めなくなる。検査（27.2）は8段それぞれの答えを表として固定している。

## D5. 指標タブとカレンダーの当たり判定（§5）— 実測で2件直した

Browser pane 375×812 の実測で **§5（44×44・例外なし）を割っていた2件**：

| | 実測（直す前） | 直し方 | 実測（直したあと） |
|---|---|---|---|
| 指標タブ「重心」「音量」 | **30 × 44** | 行の `gap` を 0 にして左右へ 22/2 = 11px の padding（`MY_DATA_METRIC_TAB_HALF_GAP_PX`）。**見た目の文字間隔は正典の 22px のまま**。下線は内側の `<span>`（ボタン全体に付けると隣と繋がる） | **52 × 44**（文字間隔 22.0 / 先頭の文字は左端に揃う） |
| カレンダーのマス | **41.3 × 34** | 縦は `CALENDAR_CELL_H = 44`（**正典の 34px は 375px では足りない**）。横は grid だけカードの padding（`--sp-4`）を食い破って地の端まで | **45.8 × 44** |

正典 `#9b` は 402px 幅なのでマスが 44.3 × 34 で、**横だけ**足りていた。
README 自身が「タップ可能要素は最小 44px 高」と書いているので、縦を 44 へ上げるのは
README の規則に従った結果。**色・角丸・gap・週の数は正典のまま。**

## D6. カレンダーの濃さは記録の有無を先に見る — §6 の書き換え

§6 は「記録が無い日 = 0、あとは `minutes / maxMinutes` で4段」と書いていたが、
**録音長が保存されていない古いセッション**（`sessionDurationSec` が null）は分が 0 になり、
「練習した日」が「していない日」と同じ色になってしまう。
`calendarLevel(minutes, maxMinutes, count)` の第3引数で**件数を先に見て**、
記録がある日は必ず 1 以上にした。

## D7. 一覧の高さ制限（§6.5 の保留を解いた）

§6.5 は「`.slist` の CSS はこの周で触らない」としていたが、専用ページで 190px の
高さ制限が残ると**画面の 1/4 しか一覧が出ない**。`.slist` 自体の規則は 1文字も変えず、
**詳細度の高い別セレクタ `.slist.is-full`** で `overflow-y: visible; max-height: none;` を
上書きした（index.css の「1セレクタ1規則」の芯を守る）。
`is-full` は**静的なクラス**（その画面では常に付く）で、**モードで切り替わるクラスは
今も `.is-select` ただ1つ**（F-106 の不変条件は1つも崩れていない）。

## D8. 「選択」は見出しの行に置いた
