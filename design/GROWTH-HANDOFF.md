## 1. アプリの事実(何を売るか)

Ficus は **サックス奏者のためのチューナー&メトロノーム**。いつもの練習で使うだけで音のデータがたまり、傾向がグラフで見える。

- **計測**: 音程(セント)・音量・音色(倍音の構成・スペクトル重心・HNR)。メトロノームを鳴らしながら計測できる。小節の頭はグラフにも線で残る。
- **傾向がグラフで見える**: 音程のクセ・音色を振り返れる。リードメーカー別・リードごと・時期・音量などの軸で集計できる。**S.Sax / A.Sax / T.Sax / B.Sax** ごとに集計できる。
- **リード管理**: 自分のリードを登録して比較する。
- **コミュニティ**: 他の奏者のデータと自分のデータを比べる。みんなが使っている楽器の組み合わせの人気も見られる。練習した日数と時間の順位(練習王)がある。
- **はじめの案内**: 起動時に利用規約とプライバシーポリシーへ同意 → プロフィール作成(**必須**)→ 4 タブの案内。
- 音声は端末の中で解析するだけで、**保存も送信もしない**。コミュニティには数値(目安・練習の日数と時間・楽器の組)だけが載る。
- 連絡先: アプリのマイページの「お問い合わせ」または ficus.help@gmail.com。

## 4. 公開の前後にやること(順番)

**公開の前(承認を待つ間)**
1. 本番 Firestore に残るテスト奏者 8 人の削除(本人の宿題。**実施済みかは未確認**)。残っていると、公開日のコミュニティに「作り物の人」が並ぶ。
2. 本人の端末が TestFlight の**本番ビルド**のままになっていないか(本物の広告を押すと AdMob で無効なトラフィック扱いになる)。開発版は「Ficus Dev 99.0」。

**公開の日**
3. ASC で手動リリースを押す(本人)。公開後、ストアの URL(§0)が開く。
4. 本人の端末に**公開版**を入れて、起動 → 同意 → プロフィール → 計測 → 広告の帯までを 1 周確かめる。
5. **AdMob → アプリ → Ficus → アプリの設定 → App Store のリンクを追加**。リンクするまで広告の配信は限られる(SHELL-SPEC §7-E-4)。
6. AdMob の app-ads.txt が「確認済み」になるのを待つ(数日)。配信は済み:https://wind-tone-lab.vercel.app/app-ads.txt
7. 広告は公開前のアプリや新しい広告枠には**出ない(配信されない)のが普通**。公開直後に帯が空でも故障ではない(帯は出ないとき高さ 0 で畳まれる)。

**公開の後(コードの便)**
8. **レビュー導線**: src/support.js の `APP_STORE_REVIEW_URL` が `null`。公開後にストアの「レビューを書く」URL を入れる別の便が要る。評価の数・星は検索順位とコンバージョンの両方に効くので、最初の施策の候補。
9. 版を上げるたびに審査が要る(Web のように push で即反映できない)。小さな直しは溜めてまとめて出す。

## 5. 獲得で最初に検討する論点(決定ではない・候補)

1. **コールドスタート**: コミュニティの価値(他の人と比べる・順位・人気の楽器の組)は**人数が居ないと出ない**。公開日は本人以外ほぼ居ない。比較・順位が空の画面を最初の利用者がどう見るか(実機で確認)と、最初の数十人をどこから連れてくるかが最大の論点。
   - 例: 吹奏楽部・ジャズ研・サックスの先生・奏者の SNS(X・YouTube・Instagram)・サックス系のコミュニティ。**本人の人脈と発信が最初の種**。
   - 本人の裁定が既にあること: 「コミュニティの参加は『しない』が無い(既定で参加。見せたくない人はマイページの『公開』スイッチを切る)」。
2. **専用の紹介ページ**: マーケティング URL が Web 版のトップ。ストアの外から来た人に見せる 1 枚のページ(スクリーンショット・ストアへのリンク・QR)が無い。作るなら Vercel の別ページ。
3. **ストアでの見つかり方(ASO)**: 名前・サブタイトル・キーワードは入れた。公開後に ASC のアナリティクス(表示回数・ページ閲覧・ダウンロード)を見て、サブタイトル・キーワード・スクリーンショットを次の版で直す。キーワードは 100 字のうち 77 字しか使っていない。
4. **SNS 動画**: videos/ficus-promo/ の企画を書き出して縦動画にする(X・YouTube ショート・TikTok・Instagram)。
5. **計測**: ASC のアナリティクス・AdMob の収益は使える。**Firebase Analytics などの利用者側の計測を入れているかは未確認**(プライバシーの申告は「広告用のデバイス ID・広告データ・製品の操作」で、Analytics の申告は無い。入れると申告も更新が要る)。
6. **有料の広告(Apple Search Ads など)**: 未検討。無料アプリで広告収益は小さい見込みなので、費用に見合うかの試算から。
7. **口コミ**: レビュー導線(§4-8)。依頼の出し方は、計測を保存した直後など良い体験の直後が候補。**星を条件にした依頼・見返りは Apple のガイドライン違反**。

## 6. 守ること(制約)

- **事実でないことを書かない**: No.1・ダウンロード数・受賞・「録音するだけで貯まる」などは使わない。**録音はボタンを押さないとたまらない**ので「練習するだけで自動で」とは書けない(本人に 2 回伝え済み。蒸し返さない)。
- 楽器のことを「機材」「機種」と総称しない。個別に(マウスピース・リガチャー・リード・楽器)か「楽器の組」。楽器種別の表記は S.Sax / A.Sax / T.Sax / B.Sax。製品名の "Alto" などは触らない。
- リードは**共有しない**(本人「リードを共有することは絶対にない」)。コミュニティに出るのは数値と楽器の組。
- 13 歳以上のアプリ。13 歳未満向けの訴求・広告はしない。
- 広告は**自分で押さない**(AdMob の無効なトラフィック)。本番ビルドの端末で毎日触らない。
- ストアの文・画面の見た目を変えるときは、本人が判断する前に**実寸のサンプル(モック)**を見せる。本人は「見た目の判断は必ずモック」「説明を増やさない」「機能を落とさない」。
- 既知のリスク: **プロフィール作成を必須にしたまま提出**している(Guideline 5.1.1(v)「アカウント作成の強制」で差し戻される恐れ。本人は了承して提出)。差し戻されたら、審査メモの説明(design/SUBMISSION.md §4)を見直すか、プロフィールを後回しにできる形に直す便が要る。
- 個人情報: 販売元は本名。電話番号・住所などは書類にもリポジトリにも書かない。
