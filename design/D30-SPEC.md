## §1 本人の裁定（**新しい規則になるので明記する**）

`.slist` の使い手は**この一覧1箇所だけ**で、**カードの中に罫つきの行が並ぶ形は前例が無い**。
§6.6 は「カードの作法は**罫を1本も引かない**」と書いている。

**本人は案①（一覧を1枚のカードに入れ、行の罫はそのまま）を選んだ。**
したがって §6.6 の規則はこう読み分ける ── **この読み分けを §6.6 に書くこと**:

> カードの作法が引かないのは **群の境界の罫**（カードと 12px の余白が群を切る）。
> **群の中の行区切りの罫はこの限りではない**（D-30 本人裁定）。
> 一覧は「1つの群」であり、その中の行を分ける 1px は群の境界ではない。

## §2 やること

### 2.1 面の名乗り

`src/App.jsx` の `AnalysisLabView` 内、すべてのセッションの `return`（`:14372` 付近）:

```jsx
<div className="surf-rule">     ←  "surf-card" へ

```

**セッション詳細の `return`（`:14324` 付近）とは別の箇所。** D-29 が触るのはあちら。

### 2.2 一覧を1枚のカードに入れる

`AllSessionsPage`（`:14839`）の `<div className={listMode ? "slist is-full is-select" : "slist is-full"}>`
を **`.card` で包む**。

**地の上に残すもの（カードに入れない）** ── これが案①の姿:
- 戻る導線「‹ データ」
- 見出しの行（`n件` + 「選択」のゴミ箱）
- 絞り込み（リード / 奏者のピル / クリア）

**読む物（一覧）と操る物（絞り込み・選択）が面で分かれる**のが案①の狙い。

### 2.3 行には手を入れない（**ここが案①を選んだ理由**）

`.slist-row` の `gap` / `padding: 11px 2px` / `border-bottom` / `min-height` /
`.slist-check` / `.slist-main` / `.slist-date` / `.slist-sub` を**1px も変えない**。

**唯一の例外**: 一覧の**最後の行の罫を消す**。カードの下端のすぐ内側に罫が1本残ると
「消し忘れ」に見えるため。

```css
.slist.is-full .slist-row:last-child { border-bottom: 0; }
```

`.slist` の使い手はこの一覧1箇所なので、この綴りで曖昧さは無い。
**`.slist-row` の定義そのものは触らない**（詳細度の高い別セレクタで上書きする ──
`index.css` の「1セレクタ1規則」の芯を守る。`.slist.is-full` が既に同じ手を使っている）。

### 2.4 `.card` の寸法を**インラインで上書きしない**

§6.6 が名指しで禁じている（「インラインの `padding` で上書きすると、その要素だけ作法から外れる」）。
**`.card` は定義のまま（角丸16 / padding 16 / `--shadow-card`）で使う。**

**結果として起きること（承知のうえで進める）**: 行の幅が
**375 − 14×2（ページ）− 16×2（カード）= 315px** になり、いまの 347px より **32px 狭くなる**。
副次行（`V16-3 #4 · 自分 · 12:24`）は `text-overflow: ellipsis` なので、**長い行はいまより早く切れる**。
**実機で読みにくければ本人に報告して裁定を仰ぐ**（勝手に padding を詰めない）。

## §3 F-106 / F-97 の不変条件（**1つも崩さない**）

`src/index.css` の `.slist` の節に書いてあるものをそのまま守る:

- **モードの切替は `.slist` に付く `.is-select` ただ1つ。** 祖先のクラスを増やして切り替えない
- **行ごとの更新ゼロ**（行の側は `listMode` を一切見ない）
- **モードの内外でレイアウトが 1px も動かない**（行の高さも字下げも同じ）
- **`contain` / `content-visibility` / `will-change` / `transform` を、行にもスクロールコンテナにも置かない**
  （iOS の再ペイント取りこぼしの典型要因）。**今回かぶせる `.card` にも置かない**
- チェックボックスは**モード外でも場所を確保したまま**（`visibility: hidden`。
  `display: none` にも `opacity: 0` にもしない ── 読み上げとフォーカス順から外すのが `visibility`）

## §7 あわせて片付ける ── D-29a「カードの画面に残った罫2本」

D-29 の完了条件「罫0本」は達成できず **2本**残った（セッション詳細2本 / リード個体詳細1本）。
実装は「共有部品の中身を触るな」（D29-SPEC §3）と両立しないとして**手を止めて起票した**。

### 7.1 呼び出し元（統括が実測）

| 罫 | 綴り | 使い手 | カードの作法か |
|---|---|---|---|
| 指標タブの下 | `bordered`（`App.jsx:13304`。`MetricTabCard` の中） | セッション詳細（`:15223`）/ リード個体詳細（`:12034`） | **両方カード** |
| 同上 | `bordered`（`:11355`。**別の呼び出し**） | リード比較 | 罫（触らない） |
| 同上 | 渡していない | My Data（`:14031`） | カード |
| タイムラインの上辺 | `borderTop: 1px solid var(--c-rule)`（`:8498`） | **セッション詳細だけ**（`:15236`） | カード |

### 7.2 裁定

**両方とも外す。** 結果、カードの作法の画面は**罫0本**になる。

- **`:13304` の `bordered` を渡さない。** 理由2つ:
  - **D-9y で本人が「指標タブの下の罫は両方外して」と言った当の罫**。My Data では既に外れており、
    同じ部品なのにカードの画面どうしで罫の有無が割れている
  - **リード比較は別の呼び出し（`:11355`）なので巻き込まれない**（罫の作法のまま `bordered` を持つ）。
    → **`bordered` は「罫の作法の画面が渡す」**という読み方に揃う
- **`:8498` の `borderTop` を外す。** コメント自身が
  【N-9】「カードの箱 → 白地+上辺の罫1本（**計測/リード/My Data と同じ文法**）」と書いており、
  **罫の作法のための部品**だと明言している。カードの中では矛盾する。
  使い手はセッション詳細1箇所だけなので、他画面に波及しない

**`MetricUnderlineTabs` の `bordered` 引数そのものは残す**（リード比較が使っている）。
**選択中のタブの下線（選択の合図）とは別物**なので、そちらは1px も触らない。

### 7.3 検査

- カードの作法の3画面（セッション詳細 / リード個体詳細 / すべてのセッション）に
  **罫が1本も無い**こと（`borderBottom` / `borderTop` / `--c-rule` / `--c-line` の横線）。
  **ただし §1 の裁定どおり、一覧の行区切りは罫ではなく「群の中の行区切り」として数えない**
- **リード比較は `bordered` を持ったまま**であること（罫の作法の画面は変わっていない）
- 選択中のタブの下線が**残っている**こと（選択の合図を消していない）
