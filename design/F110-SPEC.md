## F-110 セッション詳細（正典 = 案A をベース、属性だけ案C）

**本人指示**: 「セッション詳細はA案をベース。中断の属性3行の部分だけC案の1行案を採用」

確定する形（`detail-and-reed-proposals.html` の 案A と 案C を合成）:

1. **見出し（案A）**: 日時を主役に `08/14 23:26`（20px/600、日付が大・時刻が小）。
   その下に副次行 `自分 · Vandoren-3 #5 · Alto · 26:14`（12px/--c-ink-3、時間だけ --c-ink-2）。
   下辺に罫1本（`--c-rule`）。
2. **「このセッションの平均」（案A）**: 見出しラベル（11px/--c-ink-3）+ **4指標の数字の列**
   （平均差分 / HNR / 重心 / 音量。値18px/600・単位10px・ラベル10px）。下辺に罫1本。
   タップで音名軸グラフに切り替わる既存挙動は**維持**。目安の破線・Δ も**維持**（My Data 側だけ N-8 で外した）。
3. **属性は案C の1行**（本人指示の芯）: ラベル+値の3行（奏者/リード/日時）を**やめ**、
   **1行に畳んでシートで変更**する形にする。正典 案C の該当行:
   `奏者 / リード / 日時` … `変更 ▾`（`.kv` の作法。左12px/--c-ink-3・右13px/--c-ink + ▾）
   - タップで**1枚のシート**が開き、その中で奏者・リード・日時を変更できる
   - シートは既存の作法（下から出る・下スワイプで閉じる = F-88/F-90 の `useSheetDismiss`）
   - **ネイティブ select / datetime-local の中身はそのまま**（iOS の実寸問題を新しく作らない）
   - **機能を落とさない**: 奏者の追加（＋名前を入力）・リードの未紐付け・日時編集の全機能
4. メモ・フレーズタイムライン・音階ごとの平均・目安に設定は**位置も機能もそのまま**。
5. 「★ 目安設定中」等の状態表示は**消さない**。

## F-111 リードタブの「追加」を浮かせる（正典 = 案D）

**本人指示**: 「リードタブ追加はD案で」

- `＋ リードを追加` を**画面右下に固定**（スクロールで動かない）。
  正典 案D の `.fab`: 高さ44 / `padding: 0 18px` / `border-radius: 999px` /
  地 `--c-accent` / 文字 `--c-on-accent` 13.5px/600 / 影あり / 右20px・下は**下部ナビの上**
  （`calc(var(--nav-h) + env(safe-area-inset-bottom) + --sp-*)` で置く。直書きの数値を作らない）
- **一覧の末尾にあった「＋ 追加」は撤去**（二重に置かない）
- **最下段のタイルに重ならないよう、一覧の下に余白を確保**する（fab の高さ + 余白）。
  重なっていないことを実測で示すこと
- 当たり判定 44px（§5）。`aria-label` を持つこと
- **リードが0枚のときの空状態でも fab は出す**（そこからしか追加できない状態を作らない）

## 性能改善（性能調査の C-1 / C-2a / C-3 / C-5 / C-6。**すべて表示の追従を鈍らせない**）

計測は `design/BACKLOG.md` の性能調査記録を参照。**計測値・記録される数値は1bitも変えないこと。**

### F-112 詳細カード用の4状態を根の再描画から外す（効果最大・実測 無音時 −41%）
`setVolumeDb` / `setCentroidHz` / `setHnrDb` / `setHarmonicLevels` は毎フレーム根の state を
更新しているが、**読み手は `detailOpen` の内側だけ**で既定は閉じている
（＝画面に出ていない値のためにアプリ全体が毎フレーム再描画されている）。
- ref に貯め、**`detailOpen` が true のときだけ**購読する末端コンポーネントへ渡す
- **`detailOpen` を開いているときの表示の追従は今と同じ**にすること（間引きは不可。本人指示）
- frames への記録は tick 内のローカル変数から取っているので**計測は不変**

### F-113 PitchRing の静的 defs を作り直さない（実測 −1.3ms/frame）
`RING_GLOW_FALLOFF/GRAINY/SMOOTH_STOPS`（各45 stop）+ 4つの mask + feTurbulence filter を
`useMemo(..., [uid])` に閉じ込め、**同じ要素参照**を返す。
- 試作で **DOM が完全に同一**（256要素 / 225 stop）であることが確認済み。実装後も同一を実測で示すこと

### F-114 detectPitchMPM のバッファ使い回し（毎秒 11MB の確保を消す）
`re` / `im` / `sq` / `nsdf` を関数プロパティに持つ。
- **必ず**: `re.fill(0, W, N)` と `im.fill(0)`、`nsdf[0]/[1]/[maxLag+1]` の明示ゼロ
  （忘れると前フレームの残骸を読む）
- **出力の同一性を検証すること**: 掃引・掃引+雑音・雑音のみ・微弱音+雑音・無音の
  850フレーム以上で `freq` と `clarity` を `===` 比較し、差異0を示す
- Chrome の交互測定では時間差を検出できなかった（確保量が減るのは確実）。**iOS での効きは実機待ち**と明記

### F-115 Wake Lock の解放漏れ（**電池の主犯**）
メトロノームを付けたまま別タブへ移ると**画面が消えなくなったまま戻らない**
（実測: request 1 / release 0）。MeasureView のアンマウント後始末が `releaseWakeLock()` を呼んでいない。
- アンマウント時に必ず解放する。**正規の停止操作での解放は今どおり**動くこと
- 検査: 「アンマウントの後始末が解放を呼ぶ」ことを固定

### F-116 MetroPendulum は「変わったときだけ書く」
停止中も毎秒 730 回 `setAttribute`（**74.3% が同値の書き戻し**）。
- PitchRing の光が使っている `lastKey` 方式を同型で当てる
- **停止して落ち着いたら rAF を張り直さない**（次の START で張る）
- **拍の見え方・タイミングは1ミリも変えない**こと（F-100 の全拍強調・1.1倍を維持）
